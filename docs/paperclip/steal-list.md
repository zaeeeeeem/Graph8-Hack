# Steal List — patterns to copy into our Next.js portal + Slack bot

Facts and options only. No final decisions — lead picks.

| # | Pattern | Source | What it is | Effort in our stack |
|---|---|---|---|---|
| 1 | **Reusable EmptyState component** | `ui/src/components/EmptyState.tsx` | One component, icon + title + message + optional description + optional CTA button (`+` icon toggle via `hideActionIcon`). Two modes: title+message (bold heading) vs message+description (no heading). Used everywhere instead of ad-hoc empty divs. | **S** — ~40 lines, port almost verbatim to a shadcn/Tailwind React component. |
| 2 | **Status token system** | `DESIGN.md` "token layer" section, `--status-task-*` / `--status-agent-*` CSS vars | One semantic status vocabulary (running/paused/blocked/awaiting-approval/over-budget) mapped to a fixed token set, reused identically in badge, row, chart, log — "operator learns the vocabulary once." | **S** — we only need ~5 states (queued/running/waiting-approval/done/blocked); define as Tailwind classes or CSS vars once, reuse across Slack emoji + web badge for 1:1 visual parity. |
| 3 | **Approval queue + card UX** | `ui/src/pages/Approvals.tsx`, presumably `ui/src/components/ApprovalCard.tsx` | Two-tab list (pending / all) via URL segment, badge count of pending, approve/reject mutations that invalidate query cache and navigate to `/approvals/:id?resolved=approved`. Inline `actionError` state shown instead of toast. | **M** — maps directly to our "[Approve] [Edit] [Skip]" Slack card + a mirrored web approvals list; the URL-segment tab pattern and optimistic-cache-then-navigate flow are worth copying as-is. |
| 4 | **Budget/cost page** | `ui/src/pages/Costs.tsx` (1132 lines — feature-rich) | Full-fledged cost dashboard; too big to copy wholesale but worth a quick skim for a "spend per agent per day" table/chart shape before we build our own from scratch. | **L** to replicate fully; **S** if we only borrow the *shape* (table: agent, spend today, budget cap, % used, status). |
| 5 | **Org chart page** | `ui/src/pages/OrgChart.tsx` (673 lines) + `.production.tsx` variant, `scripts/generate-org-chart-images.ts`, `scripts/generate-org-chart-satori-comparison.ts` | Full interactive org-chart renderer; they also generate static PNG org-chart images via Satori for lightweight embeds (Slack-friendly!). | **M** — for our 5-agent flat-ish hierarchy, a static Satori-rendered PNG (posted once at `/hire-sales`) is far cheaper than porting their interactive chart; steal the "render org chart as an image via Satori" idea, not the component. |
| 6 | **Wording discipline: one canonical noun** | `DESIGN.md` Principle 7 | "Canonical term is *task* (never *issue* or *ticket*)... Buttons name the action ('Approve hire,' not 'Submit'). Empty states say what to do first." | **S** — pure copy-editing discipline for our own copy (e.g. always "task", never "job"/"ticket"; button labels are verbs+object). |
| 7 | **Contextual feedback / no redundant toasts rule** | `DESIGN.md` "Contextual feedback" section | Don't toast a run/task state already visible on screen; a terminal outcome delivered >5 min late is "historical," refresh silently, no toast; cancellation is neutral gray not red. | **S** — directly informs our Slack + web dual-surface design: don't double-notify (Slack thread reply already *is* the notification — web UI shouldn't also toast the same event). |
| 8 | **Live updates via WebSocket + query-cache patch (see architecture.md)** | `ui/src/context/LiveUpdatesProvider.tsx` | Patch TanStack Query cache directly per event instead of refetching; batch invalidations; poll-fallback when socket down; suppress reconnect-storm toasts. | **M** if hand-rolled; **S** with Supabase Realtime, since Realtime + `@supabase/supabase-js` channel subscription + React Query gives us this pattern with far less code — still worth copying the *dedup/suppress* rules, not the transport. |
| 9 | **Heartbeat = agent wakes on schedule/mention/assignment** | (see `tasks-and-heartbeats.md` from parallel worker; `doc/run-log-events.md`, `packages/db/src/schema/heartbeat_run_events.ts`) | Cron-like wake triggers logged to an append-only run-log table (`appendRunEvent` in `server/src/services/heartbeat.ts`). | **S** — for our Slack bot, a simple cron (`node-cron` or Trigger.dev, per `docs/IMPLEMENTATION-PLAN.md`) firing "Head of Sales" once/morning is the direct analog; log each fire as a row in Supabase `events` table for the standup + audit trail. |
| 10 | **Slack persona posting (multi-bot-as-one-app)** | covered fully in `slack-and-integrations.md` (parallel worker) — flagged here only as a build-time note | Not this fork's file; just note that whatever pattern they use for "one Slack app posts as multiple named personas" is highest-leverage to steal since our whole product hinges on 5 distinct agent identities in 2 channels. | See other file for source paths. |
| 11 | **Form/wizard footer convention** | `DESIGN.md` "Form and wizard footers" section | Save&exit/Cancel left, primary action right, one shared footer row per step, never split across parent/child. | **S** — applies directly to our onboarding wizard (`/hire-sales` web equivalent, if we build one) and any settings forms in the Agent Office portal. |
| 12 | **Machine-value formatting rule** | `DESIGN.md` Principle 6 | IDs, costs, token counts, timestamps always render via one shared monospace/format helper, never ad hoc per screen. | **S** — write one `formatCost()`, `formatTimestamp()`, `formatTokenCount()` util in `shared/` and use everywhere (web + generated Slack text) so numbers look consistent across both surfaces. |

## Explicitly NOT worth copying (for a few-hour build)
- Their Drizzle multi-layer contract-sync discipline (`AGENTS.md` §5.2) — too heavyweight; we have one Supabase schema and one `shared/types.ts`, per `docs/IMPLEMENTATION-PLAN.md` 1.2.
- Paperclip Runner (separate Rust process + PRP protocol, `doc/architecture/paperclip-runner.md`) — massive overkill; we call Gemini/Claude directly from our Node server.
- Docker/Daytona sandboxing (`doc/architecture/paperclip-runner-daytona-networking.md`) — our agents call graph8's API, they don't need a sandboxed exec environment.
- Full adapter-per-LLM-provider package system (`packages/adapters/*`) — we only need one `llm.ts` (Gemini) per `docs/IMPLEMENTATION-PLAN.md` 1.5.
